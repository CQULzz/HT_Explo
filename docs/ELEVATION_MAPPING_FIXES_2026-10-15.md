# 高程、历史融合与实时性修正

本次修正针对地图坐标、跨楼层融合和旧数据被当成新数据的问题。不能把红色减少直接解释为探索更好：严格未知保护会增加灰区，远处条纹误差仍有残留。

## 已修改

- 修复 CuPy 导出与 ROS 发布器重复翻转两个坐标轴的问题。真实 CUDA 单点 `(1.01,0.31)` 原先出现在约 `(-1.02,-0.33)`，现在落入正确的 4.09 cm 格子。
- 历史图使用稳定的世界格子索引；旧浮点取整在实际 291 格输入中会重复、跳过部分格子。
- 每个 XY 最多保留四个高度模式，避免一楼与二楼高度直接平均。局部裁图结合当前观测、近车地面平面和里程计 Z 选择表面；坡道不按固定楼层高度分桶。
- 保存每格真实扫描观测时间，重复发布不会让旧格子变年轻。
- 使用保边双边处理减弱小幅纹理。保留测得的明显高度边缘；不可靠孤立点、楼层选择冲突和已知障碍过时产生的空洞保持未知，禁止网络补成可走平地。新测得的向上边缘不会被历史均值压低。
- 点云和定时器分属不同回调组，TF、点云和周期任务使用三个执行线程。GPU 地图操作和完整快照受锁保护，TF 等待、ROS 序列化不占地图锁。周期位姿查询不再等待过期扫描的 TF。
- 已注册世界点云使用可靠队列；普通原始传感器仍支持 best-effort。地图头时间戳来自最后成功融合的扫描，扫描中断不会被地图发布心跳掩盖。
- HT 桥接和模型已放入本仓库 `tools/ht_cupy_bridge`，不再从相邻 bridge 目录导入。CuPy 保持独立工作空间，通过版本化补丁安装。

## 验证

Python 高程、表面选择及集成回归 42 项通过。CuPy 真实 GPU/ROS 序列化、观测时间、QoS、周期 TF 测试 7 项通过。

原版 TARE 的同一份 600 秒原始记录已重新处理：3149/3149 帧点云融合，520 组保存快照中 CuPy、高程裁图与 HT 时间戳全部一致。历史图保存 1382405 个 XY 格子、1659120 个高度模式，其中 275998 个 XY 保留间距超过 1.5 m 的多个表面。

这份离线对照沿用原版车辆轨迹，不代表当前 HT 的探索里程。498 个匹配秒中，低概率面积 35.56%→21.50%，未知 4.35%→33.66%，高概率 60.10%→44.84%。旧地图本身存在坐标镜像，不能作同一物理格子的逐格性能对比。

实时性修正后另做 45 秒 HT 控车短测：4.99 m，状态均为 HT_ASSISTED，未宣告探索完成。精确扫描时间窗口内录包 325 帧、接收回调 325 帧；324 帧完成融合，最后一帧在收尾被中断。接收排队中位数 0.056 s，P95 1.035 s，最大 1.797 s。之前可靠队列单独启用时会积压约 6 s，因此不能仅靠加大队列宣称解决实时性。

## 重跑

```bash
source /opt/ros/jazzy/setup.bash
python3 tools/install_elevation_fixes.py --workspace /path/to/elevation_mapping_cupy_ws --build
python3 presentations/run_ht_validation.py --duration 180
```

脚本启动全新 Garage、当前 HT/XYθ 规划和跟踪器，录制点云、地图、实际规划路径、控制许可与相机，结束后生成视频。结果在 `presentations/scheduled_results/ht_validation_时间/`，大包和视频不提交到 Git。八个模型通道的实车物理方向仍需标定，视频用原始通道编号展示；XYθ 路径来自实际发布的姿态序列。
