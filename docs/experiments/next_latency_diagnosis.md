# 下一轮：先补证据，再决定实时性修改

阶段23完整600秒仍有短停。最严重一帧在进入HT回调前已经旧5.7907s，该帧融合/推理/发布0.2017s；CuPy统计同一约543秒区间新增最大扫描回调3.404s、地图发布3.032s、方差更新3.033s、扫描排队5.436s。当前统计把锁等待和计算混在一起，不能据此确定GPU算力、锁持有者或内核就是根因。

下一轮保持阶段23规划、HT模型/门槛、融合算法和输入队列，先做同场景600秒诊断复跑。新增可选CuPy计时启动包装器，记录每次地图锁等待/持有、回调墙钟与线程CPU耗时，同时记录原有`/runtime_breakdown`。包装器导入独立CuPy工作区安装模块，未替换其源码、锁策略、话题或时间戳；默认关闭，可由`HT_PROFILE_CUPY=1`启用。记录器本身有小量开销，此轮作为诊断重复，不能包装成实时性优化收益。

包装器已用实际安装模块导入，并检查并发等待、嵌套锁、异常释放与回调记录。真正根因仍待完整实验时间线核查。

发布过程中还发现版本说明自动同步与大数据上传并行时，新附件被误报为旧附件变动。说明同步现在只要求已经完成上传的旧附件集合保持不变，允许新增附件；原始上传工具仍逐个核对远端大小与SHA256。这个发布修正不改变导航。
