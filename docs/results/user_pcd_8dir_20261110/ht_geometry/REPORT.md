# HT放行是否意味着几何也放行：离线逐点对照

没有发现这种严格包含关系；在本轮统一足迹的点级对照中，已经找到HT完整门禁放行、几何包络内仍有障碍的反例。这里的“几何”明确指用CMU原地形高度阈值及实际PCL预处理产生障碍，再按统一0.45米圆形足迹核验；它不是对CMU整个路径库对应表、投票和路径组评分的一比一复现。因此该结果说明两套点级判据存在分歧，不是逐条原生路径通过/拒绝率，也不是真实地形通行标签。

从既有600秒用户点云场景MCAP选取15个时刻，覆盖行驶和停车阶段，未启动仿真、跟踪器或底盘。每组HT与terrain_map的测量源时间戳完全相同，配套里程计源时间差不超过25ms；HT消息收到时源龄最大0.54943秒，低于原1秒门限。

**对照口径。** HT通过要求ht_valid、完整足迹有物理支撑、无occupied，以及所查方向概率≥0.5；物理足迹采用原Gate的0.45米加网格离散余量。几何输入沿用实际useTerrainAnalysis=true/useCost=false：先保留距机器人4.25米内、intensity>0.15的地形点，再调用实际PCL VoxelGrid做0.2米体素化。统一0.45米圆形足迹内至少2个障碍体素记为几何拒绝，0个记为未检出障碍，1个单列。2个是本对照的点级门限，与原pointPerPathThre数值一致，但原代码实际上对路径对应表计数，不能把两种语义等同。

仅比较HT有效、距源机器人不超过3.8米、离声明任务边界超过0.45米的格点，避免拿几何裁剪外或边界外的位置制造反例。8个方向分别计数；不同帧及同位置多个方向高度相关，数字不代表独立试验次数。

| 帧-位置-方向样本 | 数量 |
|---|---:|
| 完整HT放行 | 1,258,254 |
| 其中几何圆形包络未检出障碍 | 1,150,730 |
| 其中几何包络内≥2个障碍体素 | 93,482 |
| 其中几何包络内仅1个障碍，单列 | 14,042 |
| 几何未检出障碍，但HT拒绝 | 106,318 |

按上述口径，HT放行样本中约7.43%触发几何包络拒绝条件。这不是HT误判率：两者使用不同表面/障碍处理，几何标签也不是真值，且含重复帧和方向。以“至少一个方向HT放行的位置”计，187465个帧-位置样本中28836个存在该几何冲突，约15.38%；不能混用点数与方向状态数。

**具体反例。** 约59.090秒，同一测量时刻的格点中心为(2.988304,-12.526316)。HT方向0/3/7分别约0.862/0.953/0.965，支撑有效、occupied=false；而0.45米几何足迹内有6个障碍体素，最近距中心0.30339米。这6个体素的地形高度值约0.15098～0.15622米，刚超过CMU的0.15米门限。这种较小高度差可以导致几何硬门限拒绝，同时HT仍预测高通过概率；没有真实车辆标签，不能据此判定哪边正确。

源码解释也符合该现象：CMU几何采用terrain_map的相对高度门限；HT从另一条高程质量、历史融合和神经网络链路产生方向概率，其ht_obstacle层并不直接复制CMU的0.15米障碍分类。因此一个场景里HT挡住更多路径，不意味着其放行集合天然包含在几何放行集合内。

当前规划层仍保留先几何候选筛选、再HT检查的流程。该流程中的候选交集不能拿来证明“HT模型独立判断一定满足几何条件”；先前2854条非零候选的审计核验的是HT门禁，也没有独立证明所有最终控制轨迹的几何扫掠。
