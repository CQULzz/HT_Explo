已经使用用户录包点云构建的场景完成600秒采集，但持续导航没有通过。车辆行驶24.482米，约58秒后停在(2.994,-12.534)，此后约542秒没有恢复，结束仍未完成探索。这是本轮暴露出的具体失败，不能沿用CMU indoor上一轮成功运行的结论。

自由体积沿用0.5米体素、最多1Hz/1024射线/12米的采样并集口径，共匹配515帧，是观测代理指标，不是真值覆盖率或完成条件。最后移动时间按0.5秒采样CSV、距最终里程相差超过1厘米估计，约57.965秒。

**地图找到了什么。** 当前Linux目录及只读检查的两个Windows分区没有找到用户独立原始PCD。历史工程记录指出，之前用过`20261103_190624`录包导出的`local_map.npy`。从项目既有 [GitHub Release](https://github.com/CQULzz/HT_Explo/releases/tag/ht-scout-pcd-fix-20261105-v1) 选择性恢复了该数组、地面/障碍网格、旧场景及起点元数据；每个恢复文件匹配历史SHA256，库存JSON也匹配仓库发布回执。未下载或重新核验全部历史分卷。

数组包含56849个有限XYZ点，SHA256为`a30eb5576c23ae2c0a688299611e4defbc266761f277befe4ff8d9dd3acf647d`。另无损导出为本机`runtime/recovered_recorded_map.pcd`，逐值回读与数组完全相同；这是明确的NPY转PCD，不冒充遗失的原始PCD。

**本轮场景范围。** 原数组水平跨度超过250米，但恢复的历史网格仅约±15米。本次实际使用该30×30米网格，地面4781个三角形、障碍69856个三角形，网格字节保持原样。沿用历史地面最长连接边0.8米、障碍体素0.16米；空洞和未建网区域没有补成无限平地。显式任务边界为±13.5米，通过上游TARE已有导航/覆盖边界接口提供；首次TARE参数导出因发现延迟返回Node not found，失败文本保留；随后另存verified导出，确认相关边界开关为true。边界限制来自场景裁剪，不来自HT分数。

保留原XY起点(0.1102,0.1363)，由测量三角网求得起点地面z=-0.78258米，CMU传感器初始高度为地面上方0.75米；当前检查半径及离散余量内的1305个起点支撑样本均有测量三角形。CMU随后按原地形跟随更新高度。因此本轮不能称为对整张250米地图的测试。

**为什么停住。** TARE后续目标约为(-2.005,-6.175)，已经位于声明任务区内；车辆没有宣告完成，却一直没有可执行局部路径。局部规划器持续出现`HT_DIRECTION_LOW`，同时也有少量占据和源龄拒绝，完整记录保留。不能简单解释为“目标在裁剪区外”，但裁剪和重建对模型分数的影响尚未通过另一套几何对照排除。

约333.7秒的停车快照中，当前车头152.20°查方向3（中心135°）得0.939，车体范围缺测=false、占据=false、上下文有效。对应方向4（中心180°）仅0.224；候选路径车头到约160°时会进入这个方向，因此即使同位置最佳方向约0.962，该候选仍会被拒绝。此快照发生在停车以后，不冒充首次停车状态；实际路径拒绝及其精确源地图另由MCAP核对。

当前接入只筛选CMU原有目标导向路径组，并检查跟踪命令。它没有新增通用的HT局部搜索、退让或脱困规划。该位置显示：当前位置符合约束，并不保证现有路径库能提供一条后续姿态也符合约束的路径。跟踪器此时的`HT_ALLOWED`大多表示零命令及当前位置通过检查，不能理解为仍在行驶。

只读静态快照探测表明：由152.20°向右转到目标方向约128.17°，在该快照下仍在允许航向范围；随后沿该方向的1.38米采样前缀通过，1.40米处出现占据拒绝。这提示可以调查原地对齐、退让或局部重搜索，但它没有验证动力学、刹车包络、未来地图或完整绕行路线，本轮也没有把这些假设动作发给车辆。

**八方向约束的核验。** 独立重算29771条候选命令，29567条获准，其中2854条为非零候选；获准候选未发现违反0.5概率门限、0.45米物理足迹、上下文或1秒源龄条件，未解析到源地图的命令为0。最低获准扫掠分数0.58633，最大获准源龄0.99837秒。另有1912条“当前方向低于0.5而最佳方向不低于0.5”的实际拒绝记录，其中1907条匹配到精确源图且分数一致，5条没有在该审计缓存中匹配，不计为已核对。这些只证明执行了配置的规则，不证明模型概率等同真实可通过性，也不证明已经具备恢复能力。

**版本与边界。** 本轮代码冻结提交`dd8ae80`，分支`sim/user-pcd-8dir-20261110`。导航算法、权重和二进制沿用已测最小八方向版：上游TARE `b6760adb`（已有Frontier参数声明补丁）、CMU AEDE `158e67b`、局部路径/命令HT检查。速度0.5m/s、半径0.45m、概率门限0.5、地图时效1秒；沿用64线向下传感器和4Hz mapper。只替换地图、原起点高度及声明场景边界，没有降低门限或修改HT推理。底盘仍是CMU的v/ω简化运动学，没有复刻真实Scout滑移及雷达误差。

历史同地图实验使用Scout模型、不同传感器及旧XYθ导航配置，指标采样也不同；本轮与之不构成同参数性能对照，也不与另一CMU indoor场景的281.9米作排名。

136个冻结文件在运行后校验未变化。600秒内没有子进程提前死亡。录包正常关闭，10.9GiB、626.23秒（包含准备段）、334433条已录制消息，逐文件SHA256保留；订阅端存在采样/消息遗漏，不声称所有话题无丢帧。停止录包后仍发生CMU节点context退出-6及sensorScanGeneration退出-11。Gazebo相机插件因缺少camera_info_manager库未加载，激光导航仍运行；本轮视频是实际遥测可视化，不是相机录像。这些问题均记录，未包装为全流程无异常。
