# CUDA上下文与固定启动区域：离线结果

用户要求CUDA提速，并把起点稍扩大，前30秒不随HT观测变化。实车分支候选；没有设备、仿真、控制或车辆运动。

## 修改

CUDA实现上下文最近点/距离/两轴支撑窗口。保留SciPy的列优先、行次优先距离平局规则及滤波舍入，DLPack将输入直接交给同一CUDA流的模型，三张支撑掩码回CPU。auto不可用时告警回到NumPy，显式cuda失败则拒绝启动。实际测量每帧确认使用cuda，模型FP32、原权重与0.5门限不变。

实车默认半径1.5m、有效期30s、ht_startup_assume_traversable=true。任务首次开始锁定世界锚点，范围固定；30秒内圈内HT低分、HT障碍、缺测不会撤销许可，离圈也不提前退役。30秒整恢复正常检查。标志进入共享StartupPrior消息，晚加入使用剩余时间，重复开始不刷新，策略/期限冲突拒绝。地形历史的单点、批量和窗口查询一致，原观测保持。

这是HT/地形许可覆盖；独立碰撞、急停、定位/地图时效、显式drive模式与通信门槛仍有效，不能承诺无条件驱动车辆。需要同时部署重建后的规划器、跟踪器及消息接口。

## 起点：没有夸大旧样本结果

使用同一原始首帧HT及对应记录TF姿态，调用实际生产C++ HT/XYtheta逻辑，查询八个0.4m第一步目标：

|模式|起点状态|到达|
|---|---|---:|
|关闭先验|UNKNOWN|0/8|
|原1.2m未知补充先验，正确初始化|STARTUP_PRIOR|8/8|
|新1.5m固定30s许可|STARTUP_PRIOR|8/8|

不能用关闭先验的0/8充当原实车配置结果，也不能宣称新策略修复了这次车辆不动。原、新启用先验的结果在这个样本相同。首帧之外，117张输出中心格均为上下文无效；这不等于全部车身或全部方向都是UNKNOWN。未采集本次实车首拒绝链路。辅助fixture仅初始化HT先验、发布私有输入和先验状态，未调用导航许可发布、速度控制或独立碰撞云；每查询固定在源时钟，不是连续30s闭环。

新增C++测试另用明确的人工全低分/障碍/缺测地图，验证圈内覆盖、圈外拒绝、实际XYtheta第一步路线、29.999s仍许可/30s整恢复、离圈返回仍在原窗口、晚加入/到期加入、重复开始和策略冲突、地图缺失/时钟回退等。不能把人工地图称为实测安全地形。
