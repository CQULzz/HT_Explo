# 车旁随车红斑与驶过后变绿：数据归因

结论：本次截图9.8秒实际显示重算第17帧（源时间9.499675秒）。车旁随行红斑的主要直接原因，是录包/rslidar_points中反复存在的右后侧近车偏高回波，经CuPy和历史融合形成约6～10厘米的高程凸起，再被HT约2米见方的感受野扩成较大低分区。不是色标自动变化，也不能直接断言是固定真实障碍。回波究竟属于车体/附件、近场测量伪影还是随行物体，仅凭当前核验未能定性。

事实与证据：

1. 原始64帧HT推理用同一native_stream重放，保存每帧291×291精确网络输入及全部掩码；输出14层对之前视频来源逐数组核对，64/64精确一致。只增加上下文记录，没有生产代码修改。
2. 抽查12个移动时刻（约5.60～26.61秒），每帧过滤后仍有17～27个后侧近车高点。其车体坐标中位数始终约X=−0.31～−0.38m，Y=−0.50～−0.61m，Z=−0.16～−0.22m；相对局部拟合地面高6～18cm。左右定义为车体X向前、Y向左，因此在右后侧。大多数来自PointCloud2的channel 3和4，其他通道亦有，不能据此直接判定某根激光标定错误。
3. 对应截图第17帧，精确网络输入在车周1.5m范围有23个直接观测的6～10cm偏高格子；不是未知补值产生的23格。它们在历史地图中沿车后留下短带。车旁1.5m内occupied层为0，275个格子却在8方向全部T<0.5：本片低分来自网络预测，非障碍层强制清零。左侧另一个距车至少3.06m的大红块对应实际较高结构，不能把所有红色都视作同一问题。
4. 模型以51×51格、0.04m/格的高度上下文输出一个目标格的8方向分数，邻域范围约2m×2m。因此少量局部凸起会影响其周围的预测。不能把T误解为仅由该格地面高度决定，也不能把maxθT当成车辆实际朝向的许可。
5. 对第17帧做仅限诊断的反事实：把这23个偏高观测格改成拟合地面，其余网络输入、权重和掩码不变，原1.5m范围8方向全部低分的格子从275降到9，原275格中266格至少一个方向跨过0.5；并非所有方向全部恢复。只改未知最近邻填值，275格仍为275；只消除3cm以下近地纹理仍为239。其他11个抽样帧同样显示偏高点是主要影响因素。这不证明这些点可安全删除；所有反事实未写回历史图、规划器或车辆。

“开过去就变绿”的固定世界点反例：

- 同一世界位置(−3.28,5.52)m，同一0°方向，5.5994秒T=0.04726，8.3998秒T=0.99103。
- 此点高程从−0.747765m变为−0.750060m，只差2.30mm；它的51×51网络输入邻域最大变化12.52cm，87格变化超过2cm。前后车辆距离该点从1.10m增至4.77m。
- 前一帧邻域有近车偏高短带，后一帧更新后这一结构消退，网络分数随之恢复。不能解释成真实地面先不可走、被车碾过才可走；也不是代码把走过的轨迹直接涂绿。on_odometry只更新位姿/时间健康与地面参考所需样本，没有轨迹补绿逻辑。
- 查到了144组满足筛选条件的前后帧候选，不是144个独立实验或独立位置；例子足以证明同一位置、同一角度确会随上下文观测变化而翻转。

视频本身沿既有录包轨迹回放，当前HT没有驱动车辆。因此“红区里仍有车开过去”不是本次HT规划器主动穿越了自己的硬约束；本轮没有运行新闭环规划控制。

已定位与未定位的边界：

已定位的是：偏高证据在录包点云中就存在，现有几何自过滤保留它们，建图/历史保留成凸起，HT邻域预测产生随车低分；不能归咎于本次RViz着色或只归咎于未知补洞。原始回波的物理身份、机理和正确过滤边界未得到真值验证，近车点的地面高度也是拟合参考而非实测真值。暂不扩大车体过滤框、不降低T门槛、不把近车区域强行设为可行驶。下一步应针对右后侧该坐标带核对实车附件、随行物体和近场点云，并保留真实小障碍反例后再决定处理。
