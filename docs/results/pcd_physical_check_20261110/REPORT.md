# HT/几何冲突位置：独立接触动力学核验

在原始重建网格和归档Scout碰撞模型下，图片中的例子确实能以车头135°倒车穿越；这例更支持HT放行、几何包络过于保守。另一个HT分数0.450的拒绝位置，正倒车都通过，更支持几何放行。两者都不能作为所有场景的真值。

这次使用重力、轮地接触与轮关节电机驱动车身，实际动力学计算期间没有逐帧修改底盘位姿。原CMU底盘直接积分速度更新位姿，本次没有用它作为“物理能过”的证明。视频由真实保存的动力学状态回放生成，回放渲染阶段设置位姿仅用于显示，不参与上述物理计算。

| 冲突位置与车头 | 原判断 | 独立动力学结果 |
|---|---|---|
| (2.988,-12.526)，135°，前图反例 | HT=0.953放行；几何圆形包络内6个障碍体素 | 三种摩擦下倒车均穿越1.6m，车底接触和穿透均为0；原固定正向起点有轮位落在缺测网格，正向不下结论 |
| (1.228,-1.064)，45° | HT=0.450拒绝；几何包络未检出障碍 | 三种摩擦下正倒车均穿越1.6m，均无车底接触或穿透；本模型里HT过于保守 |

第一例倒车时，经过中心的横向误差约1.54～1.77cm，车头误差约0.30～0.37°，最大倾斜约6.15～6.28°；三种摩擦的最大行进距离均约1.642m。该结果只验证此方向的局部穿越，不能据此说正向也已通过或整条探索路线都可达。

图中6个所谓“15cm障碍”的地形相对高度值是0.15098～0.15622m。但回到实际场景地面三角网，这些体素中心的世界Z比对应地面低约2.56～4.10cm，没有对应的15cm实体凸起。这里的相对高度基准与实际网格表面存在差异，不能把terrain_map强度值直接等同实体台阶高度。这支持该例几何侧拒绝过于保守，而不是HT让车穿过一个真实15cm障碍。

未完成直线试验不证明任意绕行都不可达；起点没有测量网格也不能认定真实地形是坑洞。点/朝向的HT预测同样不等于整段1.6m路线的预测，因此这些样本不用于计算HT或几何的真实错误率。尤其(5.035,-4.585)、(3.561,-6.836)存在初始接触/位姿偏移，不能用它们的失败直接宣布HT误判。

**车辆、环境和判据。** 归档SDF的车体碰撞箱0.925×0.38×0.21m，车体40kg、4轮各2kg，总48kg；轮半径0.16459m、轮距0.58306m、轴距0.498m，电机上限80Nm。碰撞几何、惯量和关节从归档转换为URDF，场景直接从原Collada提取全部地面/障碍三角形。导出OBJ坐标逐值回读与源网格一致，地图试验未补额外平面。

PyBullet3.2.7 DIRECT，重力9.81m/s²、步长1/240s、求解迭代120。以0.2m/s从中心前后0.8m穿越，2秒接地、12秒驱动、1秒停止；只有初始化放置允许设定位姿。要求穿越1.6m、经过中心横向偏差≤0.1m且车头偏差≤15°，无倾覆/掉落/明显偏离路线；干净通过还要求车底穿透<5mm、带载车体接触<0.25秒。本报告两个主要例子的车底接触、穿透均为0。

摩擦模式固定为近似旧场景的纵向0.8/侧向0.1，以及各向同性0.4、0.8；ODE的滑移参数不能直接与Bullet等同，均未实车标定。当前归档Scout比此前CMU简化车体更大，结论按此车辆明确列出，没有混同两种车体尺寸。使用静态凹三角网及电机/接触的依据见[Bullet官方说明](https://github.com/bulletphysics/bullet3/blob/master/docs/pybullet_quickstart_guide/PyBulletQuickstartGuide.md.html)。

**可证明与不能证明的边界。** 这两个主要例子已经有独立动力学通过证据，不再只是“模型分数可能允许”。但原始点云连接成三角网、障碍体素化，以及摩擦/轮胎/控制器近似都会影响结果；原网格缺测处没有真实地形标签。该测试只能回答归档车辆在这份重建场景和参数范围内能否完成指定局部动作，不能代替原始实地Scout实测，更不证明整条探索路线可达。
