# 循环8离线修改

接续`fix/scout-wsl120-20261105`，基于6e30a4f。用户授权修改尚未完成的四部分并推送。本轮完成编译、回归、纯ROS接口验证和离线场景重建。循环7账本继续关闭于6/6，仿真性能验证待下一批预算。

## 修改内容

1. 场景范围统一到scene_config.json。重建、导航边界、画面缩放和体积统计读取同一组XY范围。prepare_scene.py从原始导出数组和已核验的Scout SDF模板生成新目录，保留原起点，最大地面连接边0.8m、障碍体素0.16m。输出含来源/模板/场景/网格SHA。临时目录完成后再发布，写入失败可重试，已有目标目录拒绝覆盖。runner在启动子进程前核对范围与重建几何哈希。
2. 接通HT/TARE仿真的navigation_boundary与coverage_boundary，显式启用前沿及表面覆盖边界过滤。仿真开关使用simulation_boundaries=true，要求use_sim_time=true。已有连续位姿碰撞检查也使用导航多边形。覆盖和导航边界回调完成后发布tare_boundary_status，adapter等到双方应用回执才允许启动。
3. observer按配置裁剪、缩放和统计。新体素键使用场景维度编码，修复大场景中旧1000固定进制可能产生的键碰撞，metric_geometry.json记录编码和原点/尺寸。全局0.2m体素相位和15m射线长度保持默认。旧运行目录可按历史30米设置读取，历史产物原样保留。runner使用当前项目的adapter/observer入口，并冻结实际使用的配置快照与场景资产。
4. 启动条件增加新鲜odom、registered_scan和对应方法的地形输入。源龄与接收龄均≤1秒，就绪持续1仿真秒后释放，START_GATE.json只记录一次原始源时刻。时钟回退要求重启。TARE几何组使用terrain_map_ext，HT组使用traversability。legacy选项保留旧启动触发方式供后续配对。
5. 补齐原生TARE模式的CompletionAudit，队列门槛、表面/前沿候选、复用与虚拟覆盖数量都可核对。结构化tare_decision_diagnostics记录完成条件、源时刻、采样调用数、全局可达性计数及视点碰撞/边界、连接、访问和探索单元标记。标记计数可以重叠。路由部分记录当前姿态拒绝、端点各朝向拒绝原因和前缀尝试结果，已有HT_WAYPOINT_SEARCH继续记录搜索终止和几何/HT拒绝。随机抽样日志增加有序队列/已覆盖集合指纹。
6. runner支持显式install-base，并核对实际ROS包前缀及安装入口与源码是否一致，防止脚本/安装版本混用。独立构建在本轮artifacts目录，原Linux定制CuPy与历史实验工作区继续保留。

完成规则仍使用原生全局返航、局部完成及任务时长判据；本轮增加这些判据的可核对输入。提前完成、持续阻塞和同种子波动的实际改善效果待新的闭环实验检验。
