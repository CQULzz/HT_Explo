# CMU indoor HT/TARE配对

用户要求与TARE做一次对比。安排一对重新启动的120秒、种子42实验，顺序TARE几何分支+CMU局部规划/跟踪器，然后当前HT。共享循环9已冻结的CMU indoor环境模型、Scout URDF、起点、GPU激光、真值定位、mapper、导航边界、采集器和指标配置。独立目录与账本`/home/lzz/HT_cmu_pair_cycle10_20261106`，目标两次完整采集，最多3个尝试，第三个名额仅供基础设施启动失败后的修复重试，失败保留。

控制输出上限前进0.4、倒车0.25m/s、角速度0.8rad/s。Scout仿真底盘本身的角速度限制0.5rad/s、角加速度1rad/s²，由两组共同使用。启动均等待边界应用回执及新鲜输入。TARE地形输入为terrain_map_ext，HT为traversability，均持续就绪1秒才启动。

TARE使用当前仓库几何分支及独立CMU退出修复版本，参数沿用已回归的tare_cmu_parameters.json，未知当障碍、旋转碰撞开启、局部规划器1.4m方形碰撞尺寸，附加命令桥0.84142m/±0.5m包络。HT使用既有神经门控、XYTheta及跟踪器。两组地形规则/控制器不同，比较各自端到端效果。CuPy后台建图在两组运行；HT额外推理负载及其源龄独立记录。

逐轮先核对120秒、子进程退出、冻结文件、MCAP计数/CRC/SHA及视频解码，再比较实际里程、近似观测自由体积、末段推进、旋转/停车、任务状态与诊断。一次配对的结果描述当前场景。代码与精简证据推送接续分支，完整原始数据继续保留本机。
