# 稳定建图后的精确 HT 输入审计

本文件是前一份只读报告的后续。对象改为本轮稳定 CuPy 后实际生成的208个精确网络输入context。只读原始保存结果；所有改变像素的例子仅为标注清楚的诊断反事实，未改生产源码、原图、原概率、支持掩码或规划结果。

## 精确复现

`run_data/ht_after/contexts` 每帧保存291×291的实际 `height`、observed/rejected/occupied/小孔推断、源高程/方差/年龄、历史高度、几何及8方向概率。按实际记录姿态对应的输出cell，提取其51×51精确感受野；使用同权重、eval、相同FP32规则重算。

选帧12（首个中心context有效且非occupied）、100及207，原样patch概率与保存的8方向概率最大绝对差分别为 **4.77e-7、1.49e-7、1.71e-7**。这一次确实复现了原推理输入，已替代前次保存输出高度近似重建的证据。

源文件名的整数秒/纳秒与索引stamp逐项相同。第一次脚本对浮点秒做完全相等断言失败（整数时间除法与sec+nanosec*1e-9的浮点运算顺序可差1ULP）；已改为整数时间逐位验证、浮点秒误差≤5e-7。初次失败日志单独保留，没有改源时间。

以下最大T都是8个车头方向中的最大值，门槛仍为0.5。估计地面是生产surface estimator的选择参考，并不等于新的直接地面观测。

“context有效”不代表90%像素直接测得。代码 `ht_support.py` 的规则是51×51感受野中，≥90%像素距已知值不超过0.25m，并检查不确定拒绝区；模型的nearest填值在这个合同下可以占据较大面积。这是明确现有设计，不是这次新发现了索引或输出层错误。

### 这些反例排除了哪些简单解释

- 未观测区被nearest高值填充确实存在，但**仅换这些填值并不能恢复可行性**，前两帧甚至更低。因此不能据“高值填空洞”直接认定修复为补地面。
- 仅压平近地已观测波动几乎不改变T；模型合成厘米噪声敏感的事实，不能单独解释这批实际输入的持续拒绝。
- 抹除高结构会改变模型输出，但包含删掉真实观测的物体，且中/末帧仍不通过。整图改平面当然通过，它不构成修复方法。
- 精确复现误差很小，暂未看到输入平移、绝对Z归一化、权重加载、输出中心cell或绘图颜色解释的错误。

## 历史与当前观测仍需区分

前次只读原始点证据仍有效：近车高点在原始扫描中已经存在，且在11.6–13.1秒及108.1–207.6秒出现明显点群。没有身份真值可区分人体/附件/真实结构/源异常。历史还保留了旧高结构；HT当前地图时间较新不代表每个格子的最后观测都新。当前TTL600s及保守保存旧障碍是明确行为。

若后续要改历史失效，必须先构造“当前自由射线或新的直接地面观测已证明旧障碍消失，而旧障碍仍被输出”的小反例。现有数据只有“当前无点”或源年龄老，不能据此直接变成自由地面。`association_gap_m=.6`可能在较近高度之间作历史平滑，是否是本记录主因还需重建各mode和观测时序，不能仅凭参数名判定。

## 当前结论

稳定CuPy消除了同输入地图随机分叉，但这三个实际HT输入仍包含足以让当前模型拒绝的高低结构。**本审计没有找到能据此直接、安全部署的HT代码修复，也不能保证该录包所有起点本来就应可行。** 可以发布已经验证的稳定性修复，明确停车未解决；下一候选须以有证据的历史失效/外参或观测质量反例为依据，而不是降低门槛、盲扩自车盒或抹平障碍。

证据：`EXACT_CONTEXT_AUDIT.json`、`exact_context_variants.npz`、`exact_context_sensitivity.png` 和 `exact_context_audit.py`。所有反事实的命名均含diagnostic/UNSAFE，其输出不进入规划器。
