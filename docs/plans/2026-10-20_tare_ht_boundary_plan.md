# 阶段41：HT地形输入一致性与原TARE近家返航

阶段40完整600秒及所有GitHub Release附件已远端核验。原TARE核心六函数恢复已记录：8467m³/192.93m，原TSP访问序列最多26个视点。但闭环后的构造回归明确失败，不能仅凭一轮顺畅视频验收全部接口。

1. **复现与反例。** 实际ViewPointManager加载全方向禁行带后，远侧connected=1/candidate=1，但图最短路线为空。HT筛选发生在BFS之后，破坏原TARE“候选图与连通性一致”的前提。另有源条件反例：离家1.2m时原前视函数可无输出，原PublishWaypoint仍优先HOME，HT包装却会因前视无效停车。该轮没有返航，此构造不是解释现场停车的证据。
2. **只改接口。** 同一规划周期一次获取地形顶点掩码，BFS和候选图共用；异步地图不能在两者之间再次删点。下一周期接收新掩码，执行仍实时检查最新HT。近家rush-home先恢复HOME目标优先级，再用HT规划；原前视返回标志仍原样供后续原TSP使用。
3. **保持原算法。** 六个原TARE核心函数体、访问评分/TSP/迭代次数、HT模型、高程融合、全部运动/安全限制不变。禁止通过放宽未知、换收益点或加速来掩盖问题。
4. **验证。** 真实ROS地图和ViewPointManager测试禁行带、BFS后地图更新、下一周期同步，以及新观测解除禁行；近家NaN前视、HOME覆盖和对应路线分支回归；原四项CTest与六函数SHA检查。冻结新候选后同车库完整600秒，不中途调参，保存视频、MCAP、CSV、地图、实际参数及源码/二进制哈希。
5. **报告与停止。** 对比39/40/41及历史图册，改善退步均保留；单次闭环不能证明某边界修正导致体积变化。若未触发实车式返航，明确区分单元验证与闭环覆盖范围。发布全数据、图和视频并核验远端，本机仅留最近两轮完整原始数据，然后停止本次扩展。
