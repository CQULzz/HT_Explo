# CUDA上下文与固定启动区域

本轮用户明确要求：CUDA提速，稍扩大起点范围，前30秒HT通行许可不随观测变化。仅做代码和离线测试，未启动硬件、仿真或车辆。

## CUDA

实车`ht_device=cuda`，`ht_context_backend=auto`选择CUDA上下文；`numpy`可显式回到原CPU上下文，`cuda`显式要求CUDA。模型仍使用原权重、FP32和原方向，不降低0.5门限。

新增核函数做最近已知点查询、距离/不确定掩码和两轴51格支撑窗口。距离相同按SciPy原来的列优先、行次优先规则取点；窗口中间量仍按原float32/float64次序处理。输入高度以DLPack留在同一PyTorch CUDA流上，三张发布所需掩码回到CPU。编译和模型初始化在订阅前预热。

## 起点许可

实车配置`ht_startup_radius=1.5`、`ht_startup_duration=30`、`ht_startup_assume_traversable=true`。任务开始时锁定一次世界坐标锚点和截止时间。有效期为[start,start+30s)，30秒整恢复正常HT检查。提前离圈不退役，也不移动许可圈；重发开始不延长时间。

圈内HT栅格配置位置在有效期返回`STARTUP_PRIOR`，覆盖HT低分、HT障碍标记及缺测；地形历史的单点、批量及窗口许可使用同一规则。原始高度、概率、历史观测均不改写；圈外保持原规则。规划器发布固定策略、锚点及绝对截止时间，跟踪器晚加入只能获得剩余时间，策略或截止时间冲突保持拒绝。

这里“固定可通行”限定为HT/地形许可，独立碰撞云、急停、定位与地图时效、显式drive模式和控制通信仍有独立检查。该策略不保证在其他检查拒绝时车辆仍然运动。原概率图可以继续显示红色；绿色起点圈表示临时假设许可。30秒后新观测照常参与判断。

通用C++节点默认仍采用未知补充策略，固定覆盖由实车参数启用。`StartupPrior.msg`增加策略位，部署时需同时重建、更新规划器和跟踪器，不能混用旧消息接口。
