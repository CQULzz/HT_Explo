本次以车端 `real/scout-helios32` 的实际脏工作树为基线，HEAD 为 `b1b73c7`。保留已有 `height_evidence.py`、60 秒固定起点许可、地图故障不污染拒绝边及 Frontier 参数修复。只做源码修改、车端构建和隔离域离线检查，没有启动设备或实车运动。

## 实验依据与修改范围

C 包在任务约 57 秒起出现地图过期，约 59 秒轮速归零；60 秒起点许可结束后持续无路线。C 包覆盖任务约 -65 至 +112 秒，B 包仅至约 +56.8 秒，B 不能验证许可到期后的行为。

C 的 62 秒快照中，执行支撑区域缺测 236 格，其中同源原生高程 185 格没有有限高度，另 51 格有高度；后者观测年龄中位约 561 秒、方差中位约 0.358 平方米。同源原始点云在这片区域的额外回波高于 base_link，过滤后基本消失，不能据此把车身回波视作地面。A 包还存在独立几何碰撞点，不能用单一原因解释所有停车。

- 车端另将 TARE 地形聚合中的逐格层名查找改为帧内缓存。
- 上游质量筛选新增 `denoise=False`，只省略送入历史前未被使用的双边平滑。接受/拒绝/边缘掩码照常计算，历史仍融合通过质量门禁的原始测量值；最终历史窗口的平滑保持原样。
- 历史显示地图改到 HT 主图发布之后序列化，保持原先那一阶段的高度与掩码快照和源时间。性能数据另记 `history_publish_s`、`evidence_publish_s`。这些后处理仍占用总服务时间，不能把移后发布等同于提高整链频率。

### 2. 修正新边缘与旧历史时间的关联

`retain_recent_obstacle_edges` 可能用当前真实测量覆盖历史选中高度，但之前仍把旧历史模式的观测时间交给 `qualify_height_evidence`。这会使新覆盖的离地表边缘被按旧时间隔离。

现在只对实际发生覆盖的 `retained_edges` 格，携带 `源时间 - 该格 observation_age`。其他格的历史时间不变，测量时间不改成发布时刻。回归覆盖 epoch 秒精度、旧地面、新台阶、真实障碍、未知和许可结束后停车。

这是一处经构造反例证实的源码关联错误；尚未证明它是 C 包近车大片缺测的主要来源。原 C 包缺乏真实地面支持的格仍不能由此恢复。

### 3. 逐格证据与消费者快照

新增两个按需诊断话题：有订阅者时最多约 1 Hz，保持源时间，均不参与控制许可。

| 话题 | 内容 |
|---|---|
| `/ht_real/cloud_filter_trace` | 原始有限点的真实 map 坐标、`raw_index`、`reject_flags`；0 为保留，1 为车体/遮挡过滤移除。保留与移除均不等于地面分类。用真实源时 TF，不重复滤波。 |
| `/ht_real/ht_evidence` | 与 HT 主图相同的 241×241 几何：原始高程、方差、源观测年龄、选中证据年龄、保留历史中最近接受/拒绝年龄和可重叠原因位。仅证据分级启用时发布。 |

`evidence_flags` 位定义：

| 位值 | 含义 |
|---:|---|
| 1 | 当前高程源没有有限高度 |
| 2 | 当前高程源质量拒绝 |
| 4 | 历史选取后缺高度 |
| 8 | 历史关联不兼容/拒绝 |
| 16 | 最终历史窗口质量拒绝 |
| 32 | 陈旧离地表证据被隔离 |
| 64 | 障碍候选未能确认为新鲜障碍 |
| 128 | 最终物理支撑不足 |
| 256 | 发布的 HT 上下文有效掩码不足 |
| 512 | 实测占据 |
| 1024 | 源方差无效或超出既有质量界限 |

年龄先在 float64 中计算再发布相对秒数。`last_accepted_age_s` 包括已过期但仍保留的模式，能帮助区分“保留历史里有过接受记录”和“该历史里没有记录”；NaN 不证明传感器整个生命周期从未观测。不同高度模式不能当作同一地面，仍需结合高度、方差和关联原因判断。

两个诊断话题独立限频，不保证彼此每帧时间相同。完整来源核对需保留原始点云、`lidar_filtered`、`registered_scan`、原生高程、HT 高程源及 HT 主图，只对精确同源时间、同一世界格作对应；没有对应时明确标为缺失，不能拿相邻帧冒充同帧。

原生 mapper 在独立工作区，本次没有修改其融合和清理代码。新诊断提供 HT 侧可见的来源与保留记录，并不声称已经追溯 mapper 每个内部拒绝分支。

`/ht_real/ht_map_diagnostics` 每个消费者分别报告：回调源龄、解码耗时、最新已提交图源龄、规划快照源龄、最近提交距今时间、选取快照的时刻、持有快照时长和选取次数。运行状态聚合这些报告。后续可区分“上游本来就迟”“解码迟”“新图已到但仍持有旧快照”；规划搜索仍使用不可变快照。

### 4. 起点许可结束及停车状态

实车配置仍为固定初始锚点 1.5 米/60 秒，不随车移动或自动续期。启动日志打印实际半径、时长和固定期限属性；界面倒计时仍取自规划器发布的 `StartupPrior`。通用离线工具的默认时长不代表实车配置。

规划器与跟踪器使用实际门禁解释当前位姿：

- `HT_MAP_STALE` 等地图故障；
- `HT_CURRENT_POSE_MISSING_SUPPORT`：执行足迹缺物理支撑；
- `HT_CURRENT_POSE_CONTEXT_INVALID`：上下文无效；
- `HT_CURRENT_POSE_OCCUPIED`：真实占据；
- `HT_CURRENT_HEADING_LOW_SCORE`：当前车体航向低分；
- `GEOMETRY_CURRENT_POSE_BLOCKED`：独立几何碰撞；
- 当前位姿许可成立但无可执行路径时，报告 `PATH_NO_EXECUTABLE_ROUTE`。

这些是首个拒绝原因，多个条件可同时存在；结合逐格位图和运行状态看重叠原因。没有把规划预算耗尽/失败记忆统一解释成真实障碍。

### 5. 显示口径

RViz 默认使用当前真实车体 yaw 的通道，映射参数与执行配置一致：灰色未知、橙色上下文无效、品红实测占据、红色当前航向低分。最佳方向图保留为默认关闭的诊断图，明确其不表示当前执行许可。

白色圈为连续 0.6 米诊断圈；蓝色圈及格点为 C++ 支撑门禁的离散区域（半径含 `sqrt(2)*resolution`，中心取机器人所在栅格中心）。`body` 为兼容旧工具保留的诊断圈计数，新字段 `execution_footprint` 报告执行口径和当前/最佳分数。独立几何碰撞检查另行执行，不能把蓝圈当作整套碰撞模型。地图边缘的格数只统计图内区域，边界标记为保守提示。
