# XYθ 探索目标与执行衔接

Garage 的180秒验证曾出现目标尚未抵达就切到相反方向，反复原地旋转；规划回调耗时也超过了控制许可的1.5秒有效期。本次将目标持续推进和实时执行检查分别处理。

## 目标选择

- 局部目标按世界坐标保存，避免滚动视点网格的索引变化被误当作目标身份。
- 已选目标仍能通过当前 HT/几何硬检查且持续接近时，优先继续前往，即使该目标当前收益变为0。
- 距目标0.6米视为完成这一局部子目标；新目标至少离车0.8米。XYθ搜索本身的到达半径保持原配置。
- 12秒内未向目标接近至少0.2米，或本轮没找到合法路径，就释放目标并对其周围0.8米区域设置20秒选择冷却。不会无限坚持一个堵住的目标。
- 全局引导点保留到接近或它不再出现在TARE全局路线中，减少在全局路线两端来回切换。局部过渡点按朝该引导点的推进量选择。
- 全局路线尚未建立时，从TARE的局部边界或覆盖候选集合中的远视点选取并保持一个过渡引导点，避免启动阶段没有引导点而不动。
- HT模式每轮执行一次候选集合选择及XYθ求解，避免旧TSP多轮随机优化重复执行昂贵的状态空间搜索。
- 搜索前检查候选终点是否至少存在一个受到HT支持的车头方向；把其他有覆盖收益的候选视点一并纳入筛选，去除重复目标，最多搜索8个不同终点。终点检查只是必要条件，整条路线仍需通过XYθ搜索和沿途硬检查。
- 普通目标均无路时，允许先走向侧面的合法过渡视点，不要求每一步都缩短到远方目标的直线距离。为这类恢复候选预留搜索名额，并按方位分散采样；车辆未到访的1米位置格优先。到访记录仅用于恢复目标排序，不能把未知地形当作可通行。

这里的进展判断是到目标的平面距离，不保证复杂迷宫中绕行的完整性。仍可能需要在凹障碍、远目标不可达时进一步使用全局路线的拓扑进度。

## 执行检查

`xytheta_follower` 启用HT时，使用与TARE相同的HT配置，独立接收最新HT图，在20Hz控制回调中检查车体姿态、前方1米路径及当前指令产生的短时运动弧线。地图解码在单独回调组运行。

此时旧Bool许可超过1.5秒不再单独导致停车；它不是无限续期：

| 条件 | 行为 |
| --- | --- |
| 规划器明确禁止，或 `/stop` 要求停车 | 停车 |
| 路径接收时间或源时间超过3秒 | 停车 |
| 定位接收时间或源时间超过0.5秒 | 停车 |
| 点云接收时间或源时间超过3秒 | 停车 |
| HT图超过配置的新鲜度限制或尚未标定 | 停车 |
| HT不支持当前姿态、即将执行的路径或指令弧线 | 停车 |

速度上限、HT阈值、未知区策略和地图新鲜度限制均未放宽。未启用独立HT检查时仍保留旧的许可超时检查。实车仍需标定模型通道方向和车辆参数；此实现不包含轮胎滑移或侧翻动力学模型。

重复收到同一条路径时保留执行索引；新路径到达时根据当前位置和车头方向在其起始段衔接，避免每次从最初的转向动作重来。

`/ht_follower_status` 发布实际控制状态，包括 `DRIVING`、`TURNING`、`PATH_STALE`、`HT_PATH_BLOCKED` 等，录包、视频与报告会保留它们。规划器的 `HT_ASSISTED` 只说明上层状态，不等于车辆正在行驶。

## 运行与验证

```bash
python3 presentations/run_ht_validation.py --duration 180
```

该脚本给规划器和跟踪器加载同一个 `tools/ht_cupy_bridge/ht_trial.yaml`。手工启动跟踪器也应加载相同HT配置：

```bash
ros2 run tare_planner xytheta_follower --ros-args --params-file tools/ht_cupy_bridge/ht_trial.yaml
```

`ht_trial.yaml` 中的已标定标志是CMU仿真配置，不应直接作为实车已标定的依据。

回归验证包括目标停滞/冷却/持续进展，慢规划许可下的连续执行，以及障碍、未知区、过期路径、定位中断和明确禁止情况下的停车。对比实际仿真数据：

```bash
source /opt/ros/jazzy/setup.bash
python3 presentations/compare_ht_execution.py BEFORE_DIRECTORY AFTER_DIRECTORY
```

输出行驶距离、轨迹、原地旋转/完全停车比例及未抵达前的目标方向反转数。这些指标不等于探索体积，也不能单独证明碰撞安全或复杂场景的探索完整性。
