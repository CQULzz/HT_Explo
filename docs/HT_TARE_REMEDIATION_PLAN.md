# HT–TARE 整改方案：缺测降级与可靠返航

日期：2026-09-22。审查基线：4315dd9。状态：设计方案，尚未实现；不代表修复已完成或性能已提升。

## 目标与研究依据

将几何规划、HT 通过性代价、观测有效性、任务状态分开。HT 负责增强道路选择；缺测不能误记成模型判定危险；探索结束不能误记成完成返航。

- [Prágr 等，2022](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2022.910113/full)：几何可通行模型与学习代价模型分离。本方案借鉴职责分离；缺测回退到 TARE 是本项目设计，不是论文已证明的安全机制。
- [FASTER](https://arxiv.org/abs/2001.04420)：面向未知区域规划，同时保留已知自由空间中的备用轨迹。本方案借鉴短段执行与停退路线检查；不会因为有历史路线就宣称满足 FASTER 的理论条件。
- [STEP](https://arxiv.org/abs/2303.01614)：显式建模不确定性、风险代价与恢复行为。首版保留现有 HT 软代价，不声称实现了 CVaR。
- [WVN](https://arxiv.org/html/2404.07110v1)：区分通过性估计与置信度。当前 ht_valid 是观测支持标记，分类 softmax 概率也不等于模型置信度。网络集成或分布外检测作为后续独立扩展。

本轮优先处理确定的系统问题，不重新训练学生，不把更换雷达当作算法修复。

## 证据与根因

1. stock-sensor pilot3/4：HT 中心及 0.6 m 足迹范围无有效高程支持；HT 地图和局部路径存在，但执行门控停车。±15° 雷达、安装高 0.75 m，在平地上的近地面盲区约 2.8 m。
2. 加强向下观测并排除自回波后的正式对照：TARE 平均覆盖 50.84%，HT 48.47%；HT 两次结束均距起点约 2.3 m。
3. 两组陡坡暴露均为零，这轮不能证明道路筛选收益。场景属于训练域，CMU 运动学不是 Scout 真实动力学。
4. 当前代码：execute、SolveHTTSP、GetLookAheadPoint、PublishWaypoint、publishPermission 均含 HT 就绪/有效性限制；仅改一处不能消除死锁。
5. ConcatenateGlobalLocalPath 在 HT 开启时提前返回 local_path，绕过后续返航拼接。GetLookAheadPoint 和 PublishWaypoint 也有独立 HT 分支。修改必须贯穿整条返航执行链。

## 问题 1：缺测处理与受约束降级

### 状态分离

基础导航健康、HT 数据状态、任务状态分别管理。不要继续让 ready() 一个布尔量承担全部含义。

建议增加：

- BaseHealth：定位、激光、必要 TF 和几何图是否有效，数据年龄及原因。
- HtMapStatus：FRESH、STARTUP_WAIT、STALE、BAD_LAYOUT、TF_ERROR、UNCALIBRATED、MODEL_ERROR。
- SegmentAssessment：有效长度/比例、未知长度、已知部分风险、地图年龄、几何是否可行、判定原因。
- ExecutionMode：HT_ASSISTED、GEOMETRIC_FALLBACK、HOLD。

ht_valid 仅说明观测/输入支持。高通过概率、低通过概率和未观测不能混在一起。全图故障与局部缺测必须区分；需要桥接节点健康心跳，防止把模型崩溃误认作普通启动等待。

### 默认增强策略与可选严格策略

| 情况 | 建议动作 |
|---|---|
| 激光/定位/基础 TF 失效，或几何路径不成立 | HOLD，停止并给出明确原因；任何 HT 概率都不能覆盖 |
| HT 新鲜且所需区域有效 | 使用方向性 HT 代价，保留几何检查 |
| HT 新鲜但部分区域缺测 | 该部分使用几何降级和未知惩罚；其余有效部分继续保留 HT 风险 |
| 桥接健康、启动阶段尚无足够地形观测 | 仅在显式启用增强策略时允许启动降级；记录前提与限制 |
| 曾经正常后突然长时间不更新、格式错误、方向未校准、HT TF 错误 | 默认 HOLD，不自动伪装成可接受的缺测 |
| 新鲜有效且 HT 低通过概率 | 保留既有风险惩罚；不得为选到更短路线而触发回退、抹掉风险 |

首版提供 geometric_fallback 和 strict 两种明确配置。研究主线使用前者，后者保留为消融对照。geometric_fallback 只能继承原始 TARE 的感知能力，不能保证未观测地面安全。

降级时拟使用 0.2 m/s 速度上限、0.5 m 单次执行前瞻作为初始工程设置，参数需先在独立联调场景验证后冻结；不宣称这些数值已经校准为安全阈值。累计降级距离/持续时间必须可配置、可记录，超过预算进入 HOLD/观察恢复，不能靠反复重置短段无限绕过预算。启用这种预算意味着某些真正无可观测出口的情况仍应停车，不能承诺仅靠软件总能脱离盲区。

复用 CMU /speed 接口实现速度约束前，必须核对 localPlanner/pathFollower 的 speedHandler、时延和遥控优先级，确保降速实际生效，并由单一仲裁模块管理恢复。严格停止继续通过已有停车航点/控制链实施并验证；不让两个节点竞争发布无约束速度。

### 代价与执行保持一致

保留现有形式：

J(e) = L(e) + λ × ∫(有效部分) −log(max(p(x,θ),ε)) ds + μ × L_unknown(e)

这是代价代理，不是校准后的整段失败概率；邻近预测相关，不能将其包装成独立事件概率或 CVaR。ε 复用当前数值实现。首版 λ、μ 固定沿用当前配置，不因测试结果调整。

未知部分不填 p=1，也不填 p=0，不改变原始有效性掩码。混合边仍计算已知部分的风险，不能把整条边退化成纯距离。

每个规划周期冻结一次地图快照、健康状态、策略和版本号；搜索、边代价、航点裁剪使用同一周期决策。候选执行段再次通过统一检查。若周期中发生基础故障或地图更新暴露冲突，应停止/重规划而非继续执行旧决策。记录模式切换原因并增加时间滞回，避免有效性边界导致频繁启停。

不要临时把全局 ht_enabled 改成 false 来回退。这会切换路径求解和航点逻辑，并丢掉已知风险。应在同一图和执行框架中处理每条边的数据状态；零学习代价的消融组用于隔离框架本身影响。

### 高程历史

保留原始观测掩码和每单元最后观测时间；轨迹经过不等于整个窗口已观测。历史高程必须具备位姿/地图坐标一致性及老化策略；只保留有证据的区域。当前仿真 minimum-height 累积适用于静态试验，不可直接作为动态实车融合方案。

真正没有起步观测时，明确采用原始 TARE 等级的降级假设，或要求经确认的起步区/补充传感器。禁止从场景真值初始化 HT 作为普通实验输入。

## 问题 2：任务状态与受检查的返航路径

### 明确状态

WAIT_START → EXPLORING → RETURNING_HOME → COMPLETED。

EXPLORING/RETURNING_HOME 可进入 BLOCKED；BLOCKED 保存原任务意图，恢复后返回对应状态。数据/校准等故障为独立 HOLD 原因。超过恢复预算报告 ABORTED 或继续明确阻塞，不能跳到 COMPLETED。

- coverage_complete：当前探索目标处理结束，不等于完成任务。
- returning_home：返航路径正在执行。
- mission_completed：到达起点且已经停止。

兼容处理：保留 /exploration_finish 既有“探索阶段结束”的语义，明确文档；新增 /mission_state、/mission_completed。所有评估脚本改为使用任务完成事件，避免静默改变旧 topic 导致其他模块误解。

到家条件首版建议复用 0.5 m 距离阈值，同时检查实测速度 <0.05 m/s 持续 1 秒；使用定位/里程计实测值而非零速度命令推断已停车。初始位置固定于任务启动时的有效定位，不能随重规划更新。

### 路径衔接

1. 原生 global_path 已有返航意图时优先复用；根据 keypose_graph::GetShortestPath/已有连通图生成到 home 的完整路线。检查候选图的碰撞/连通标记和失败返回值。
2. 当前局部图只负责执行返航路线在局部视野内的前缀。local_path 为空或仅 ROBOT 点，但机器人尚未到家时，必须请求返航连接或报告 BLOCKED，不能停在那里并当作完成。
3. 实际走过的路线只能作为候选，不是永久安全证据；动态障碍、定位变化以及上下坡方向不同都要求重检查。
4. 当前关键位姿最短路不应被宣传成已支持全程方向性 HT。首版可用其提供几何返航走廊，再对本地前缀施加 HT；如后续全局加权，必须扩展有向边而非借用对称距离假设。
5. 禁止默认把当前位置直连 HOME。只有完整短段通过当前几何、策略及必要风险检查时才允许快捷连接；否则沿图路线逐段返回。
6. 去程和返程方向不同，HT 按返程实际 θ 重新查询，不能直接复用去程风险数值；不得假设上坡通过就能安全下坡。
7. 遇到阻塞：停车→在当前地图重规划→在现有有效空间内选择观察/退回动作→仍无路径则报告 BLOCKED/ABORTED。不能无限旋转或穿过已知危险去追求返航完成率。

## 执行顺序与验收

### M1：统一诊断、修复返航

先增加原因日志和任务状态，修复问题 2；HT 开关两组共享任务状态及返航检查。保持感知策略和学习权重不变。

必要检查：空 local_path、只有 ROBOT 点、当前位置不等于 home；非直线返航；直达 home 穿障碍；反向坡度风险变化；返航阻塞；传感器掉线；多次状态触发不能重复宣布完成。已知可行的简单回环中，HT 开/关均应到家停车；不可达时均不得发布 mission_completed。

### M2：缺测策略贯穿整条链路

实现问题 1 的周期评估与分段回退，联动五处 ready 门控。首轮不加新的低概率硬阈值，不训练网络。已有 soft HT 风险在缺测回退中保持有效；硬筛选阈值作为后续独立消融，并只在验证集选取。

必要检查：局部未知不是高风险；几何障碍不能回退穿过；混合路径保留已知风险；基础故障和坏 TF 必须停车；预期启动缺图与模型失效可区分；模式抖动、控制输出真实限速、预算累计及恢复清零条件。默认雷达在基础 TARE 本可启动的测试中不再仅因预期 HT 缺测全局锁死；若触及降级预算，必须清楚报告原因，不能声称无条件启动成功。

### M3：冻结实验并自动汇总

基础/功能检查通过后再跑耗时仿真，保留旧结果，不覆盖。使用原始雷达作为主对照；扩展向下视场是独立条件，不能混算。

| 组别 | 目的 |
|---|---|
| A：TARE，公共任务/返航修复，无 HT | 修复后的基础基线 |
| B：统一 HT 图与执行框架，学习风险权重为零，同样的未知策略 | 隔离新框架、降级与航点逻辑自身影响 |
| C：同 B，但保留已校验的学习风险代价 | 与 B 比较 HT 预测的增量作用；与 A 比较整体集成效果 |
| D：同 C，但缺测策略为 strict | 缺测硬门控的消融 |

B 不移除基础几何约束和未知惩罚；不使用 NaN×0 等方式实现零风险。若后续加概率硬阈值，应增加单独组，不能暗中放入 C。

先跑短时联调，再建议 3 类地形×每组 5 次，交错顺序。场景应包含确实需要选择路线的坡道/台阶/绕行区；不能再次只在无人经过危险区域的场景里评价危险筛选。尽量暴露并固定 TARE 随机种子，同时承认仿真调度仍有随机性。超参数在验证场景冻结；独立地形泛化需要按地形分组重训，不能拿现有见过地形的权重冒充未见测试。

主指标：任务完成与返航成功、固定时间覆盖、真正完成任务后的总路程/耗时、未完成时停滞、危险暴露（独立定义）、HT 有效行驶比例、回退距离/时间、基础故障与HT故障原因。覆盖阶段路程与返航路程分开。可再比较达到相同覆盖量时的风险，但未达到目标的运行必须记失败/截尾，不能只保留成功组。

所有原始次数、失败和重复间波动均报告；不承诺整改后一定增加某个百分比。若回退占绝大多数行程，需要先说明实际可评价的 HT 作用范围。
