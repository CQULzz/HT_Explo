# 连续规划空间不能由最近覆盖格的标签决定

阶段45完整数据和视频已经远端核验（stage45.json，fe42313），新修改先提交[计划](../plans/2026-10-21_continuous_domain_plan.md)。阶段45的数据不改写。

## 证据链

末段真实位置约(30.891798,42.231197,0.746521)。同时间戳HT审计给出KNOWN，当前方向P=0.99932；最终碰撞云在有效高度范围内最近点距0.8014m，超过原几何半径0.641421m；最近执行拒绝已过去65.26s，超过6s失效期。

最近0.3m覆盖格中心约(30.75,42.15)，同时缺少候选与碰撞标签。旧InLocalPlanningHorizon除了范围/高度，还要求最近覆盖格“候选或碰撞”。把它用于连续碰撞查询和XYθ根状态，会在实际位置可行时返回范围外，造成INVALID_START。

原始JSON、只读重现脚本见`docs/fixes/evidence/2026-10-21_start_gate_followup/`。这里没有声称逐回调重放了所有运行内存，或所有INVALID_START都由该原因造成。

回归使用更小反例：空碰撞云、实际位置在网格/高度范围内、最近覆盖格非候选且无碰撞标签，旧代码InCollisionAtPose仍为true；旧代码失败日志已保留。

## 实现

- 保留原InLocalPlanningHorizon，原TARE覆盖、TSP和访问序列照旧。
- 新InContinuousPlanningHorizon只判断实际空间网格与原高度范围。HT搜索和连续碰撞查询使用它，避免把覆盖格标签充当连续车辆状态。
- 真正的碰撞云、边界/禁入区、HT方向/未知/新鲜度、车辆运动检查保留；没有给起点碰撞加豁免。

涉及viewpoint_manager.h/.cpp、local_coverage_planner/ht_route.cpp及geometry_pose_test.cpp。不改模型、预处理、0.5门槛、足迹尺寸、速度或搜索预算。原TARE六函数SHA另行核验。

## 验证范围

保留旧代码反例失败和四CTest结果；最终四项全通过（50.80s），六函数SHA通过，独立安装已更新。测试同时覆盖真实障碍、越界、高度越界、NaN和禁入边界；原覆盖函数在非候选格依旧返回false。
