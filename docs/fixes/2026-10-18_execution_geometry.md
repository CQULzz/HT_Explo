# 规划和执行使用同一物理安全边界（候选28）

## 已复现的问题

阶段27完整600秒，最后移动136.501秒后持续几何INVALID_START。录包中最后路线对最近几何点云最小间距0.64908m，既有安全半径0.641421m，约8mm余量；首次重叠时实际参考点偏离该路线约11.89mm，距点云0.63736m。当时HT允许位姿。规划器检查几何+HT，控制器只检查HT，存在真实接口差异。录包关联不是精确回调重放，不能把偏差、输入变化和时延各自贡献分开，也不是物理接触证明。

## 候选修改

- 执行端可靠订阅原有collision_cloud，按同一0.5m半径+半碰撞格对角线、同一上下高度范围检查当前参考点、前1m路径和反应/制动时间内指令圆弧。场景YAML限定tare_planner_node，因此显式传递共享物理参数给follower，避免作用域导致静默默认。
- 当前位姿重叠、路径重叠、指令重叠与几何缺失/超过3秒分别给出状态，实际发出完整零Twist；路线/指令失败反馈带原计划时间戳，交由已有6秒边冷却重规划。未知仍由HT独立硬拒绝，神经概率不成为软代价。
- 名义平移段与目标端点在原几何边界外额外预留0.12m，参数xytheta_tracking_margin。取值对应现有控制器中间采样点0.12m到达容差，明确为候选安全预留，不是经证明的误差上界。实际根状态和原地旋转仍用原始物理边界，绝不放行已经重叠的实际车位。
- 不改变HT阈值、物理基础边界、未知规则、3秒HT时效、速度、动作或搜索预算。额外余量可能拒绝原本几何可行的窄通道，必须记录这个限制。
