# TARE + HT 独立局部通行判定实验方案

日期：2026-11-11。用户已授权按方案执行；最多两个候选、三次正式启动尝试。

## 交付目标

原生 TARE 继续选探索目标；局部执行不再由 CMU 点云几何规则筛掉路线，由 HT 的八方向约束决定局部路线能否执行。验证它能否解除现有地图中的阻塞，以及解除后是否出现碰撞、失去支撑或方向约束失效。

不能以“里程增加”单独认定成功，也不能在 HT 自己拒绝全部路线时，假定删除几何就一定能恢复。

## 一、明确本次关闭什么

实验从已完成用户地图测试的 1747921c6be99cd8dad7d471045090c46a0e03a2 建新分支 `sim/ht-only-local-20261111`，原分支、历史记录不动。

| 项目 | 实验处理 |
| --- | --- |
| CMU 相对高度阈值、点云路径碰撞投票 | 不参与局部路径拒绝和评分 |
| CMU 几何旋转障碍限制、地形代价惩罚 | 不参与局部路径拒绝和评分 |
| CMU 原有路径库、目标方向偏好、跟踪控制器 | 第一候选保留，便于定位关闭几何的实际影响 |
| HT 八方向分数 | 保留，按预测车身朝向查询；正倒车不能混用朝向 |
| HT 障碍层、观测支撑、上下文有效性、地图时效 | 第一候选保留并分别记录拒绝原因 |
| 任务区域边界、速度/加速度限制、停车命令 | 保留；边界不再依赖被关闭的点云障碍投票 |
| 原生 TARE 候选视点、覆盖统计、全局路线与完成判据 | 本次不修改，不把 HT 回写为覆盖完成 |

这里的“HT 独立”明确指**局部通行判定改用完整 HT 输出与有效性检查**。HT 的 `ht_obstacle` 也是一个障碍判据，需要记录其生成规则，不能把这个版本称为“纯神经网络八分数、没有任何几何规则”。原生 TARE 内的几何可见性、碰撞与连通性逻辑也仍然存在。本实验回答局部几何筛选是否多余；完全移除 TARE 的几何逻辑属于另一项算法改造。

不再保留一套独立 CMU 几何否决作为暗中的执行后门。用于评价的原始网格与接触检查只记录结果、判定试验失败，不替规划器选择路线。

## 二、第一候选：只关闭 CMU 局部几何筛选

### 实现范围

- 在 `src/cmu_local_planner_ht/src/localPlanner.cpp` 增加明确的判定模式：`geometry_only`、`geometry_and_ht`、`ht_only`。正式实验使用 `ht_only`；前两种用于同帧回放核对，不重复跑已完成的原生 TARE 基线。
- `ht_only` 绕过几何路径投票、几何转向限制和地形代价惩罚，保留方向/目标偏好，再用 HT 检查拟输出的实际路径。审查 `/check_obstacle` 和手柄回调，保证它们不会悄悄切回另一模式。
- 不只改一个 `checkObstacle=false` 参数。现有边界与附加障碍也进入该点云链路，需将任务边界作为显式约束独立检查；其他外加禁行区域若存在，必须单独列明，不能静默丢失。
- 保留现有传感器回调用于规划触发，避免关闭几何时顺带让局部规划停止更新。路径可视化必须显示 HT 真正检查并放行的路线，不能继续把旧的几何 `freePaths` 当作 HT 结果。
- `ht_gate.hpp` 和 `pathFollower.cpp` 保留路径及最终速度命令检查，包括反应与制动预测。固定 HT 阈值 0.5、时效 1 秒及当前 CMU 实验的 0.45 米有效性半径，不通过降低阈值或缩小包络制造通过。
- 日志记录模式、候选数、HT 放行数、逐类拒绝原因、选中路径、地图源时间、当前/预测车身朝向及实际输出速度。

### 先做已有停车现场回放

使用用户地图约 59 秒的原始 HT、地形与里程计快照，不改变其观测值，分别核对三个判定模式。

需要回答：原先哪些路线由几何拒绝？移除几何后哪些路线通过 HT？通过的路径能否产生通过最终 HT 检查的非零控制命令？

已知 HT 单独允许过一条“先转到 135°、再向西北移动”的静态局部前缀，但这既不等于现有路径库会生成它，也不等于当前跟踪器能执行它。若回放显示 HT 仍全部拒绝，必须如实归为 HT 拒绝或候选搜索不足。

## 三、第二候选：仅在确认搜索不足时增加 HT 恢复

若第一候选仍停住，先区分地图缺测/过期、HT 方向拒绝、候选路径不足和控制跟踪失败。只有确认存在经过连续检查的 HT 可行前缀，却没有被当前局部执行链找到或执行时，才进入这一候选。

- 在局部 `(x, y, yaw)` 空间内做有界搜索，运动基元包括前进、倒车、左右弧线与原地转向，沿用当前 CMU 的差速等效运动学和控制限幅。
- 搜索状态至少表示八个朝向；运动过程按实际连续朝向检查 HT，旋转经过的中间朝向也必须通过，不能直接跳到高分方向。
- 使用同一 HT 有效性和制动约束，寻找朝向 TARE 目标取得进展的短前缀，滚动重规划。目标在 HT 窗口外时，不声称已找到到达目标的完整路线。
- 所有恢复命令经过与正常命令相同的最终检查。当前姿态无效、地图过期/缺测或无可行前缀时停车并说明原因。
- 使用有界算力预算，记录耗时与是否超时；最终命令检查不能被搜索阻塞。恢复状态区分“搜索中、执行中、不可行、数据无效”，避免持续原地往复被统计为恢复成功。
- 第一候选的失败数据与代码冻结保留，不把加入恢复后的效果全归因于删除几何。

## 四、验证顺序和轮数

以下是执行本方案时的建议上限，本次写方案不启动试验。

1. **离线回放与回归。** 使用停车快照及已收集的冲突位置；核对正倒车朝向、跨方向边界的旋转、地图过期/缺测、任务边界和最终命令。确认几何确实退出局部判定，不改动 TARE 的覆盖与完成逻辑。
2. **用户地图完整 600 秒。** 固定原场景、起点、传感器、速度和统计口径，运行第一候选；即使提前停车，也继续记录到 600 秒。记录代码、参数、二进制与资产哈希。
3. **必要时一次恢复候选。** 第一候选若证实是搜索/跟踪缺陷，修复、冻结后再做一次同条件 600 秒。若是 HT 认定不可行或地图缺测，不以降低门限代替修复，不自动扩大试验。
4. **CMU indoor 一次 600 秒回归。** 对最终候选验证原本正常的探索场景是否退化；复用已有原生 TARE 结果，不再重做无关基线。

合计最多两个导航候选、三次正式仿真启动尝试，失败也计数。预算结束交付已有结果，不无限迭代。

## 五、判定标准

| 要回答的问题 | 需要的证据 |
| --- | --- |
| 几何是否真的退出局部通行判定 | 模式与分支审查、同帧回放、实际候选/拒绝日志；不得仍用几何结果给 HT 候选提前清零 |
| 八方向约束是否仍然生效 | 按每条实际放行命令引用的原始 HT 地图，独立重算实际朝向与反应/制动轨迹；违反门限为失败，无法匹配原图的样本单独列出 |
| 是否解决原来的阻塞 | 同条件是否通过原来约 58 秒的停车区域并继续向探索目标取得位移；单纯转向、倒车往复或提前宣布完成不算解决 |
| 是否又出现有路不走 | 对持续阻塞快照做独立 HT 局部搜索，分别报告确有可行前缀、未找到、数据无效和搜索超时；不把未找到等同于无解 |
| 放行后是否真的能过 | 将新增放行的冲突路段交给原始网格接触动力学核验，记录车体接触、穿透、失去支撑、倾覆与是否完成穿越；缺失网格和初始碰撞不作通过结论 |
| 整体探索是否退化 | 里程、观测自由体积、任务状态随时间、阻塞时长、实际轨迹与视频，与同条件历史版本对比 |

现有 CMU 车辆通过速度直接积分，没有碰撞动力学，因此“CMU 画面走过去”不能单独证明可通行。已有独立接触测试用的是归档 Scout，尺寸也不同。新增局部物理核验必须注明所用车辆：只有相同车体/参数的结果才可直接比较；Scout 结果另列，不把它与 CMU 导航结果混成同一模型验收。网格缺测处不补假地面。

## 六、交付内容

- 独立实验分支、最小修改说明、可复现启动方式和冻结清单。
- 三种局部判定模式在相同停车快照上的结果，解释到底是几何误拒、HT 拒绝还是搜索/跟踪不足。
- 每次试验的完整数据与失败记录、HT 命令独立审核、轨迹/进展对比图、可播放视频，以及新增放行路段的接触核验结果。
- 结论分别说明“几何是否需要保留”“当前 HT 是否够用”“恢复是否有效”，不以一个总里程掩盖其中的问题。
