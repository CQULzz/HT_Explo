# 膨胀误拒与恢复耗时修复

基线 `5e5eef`，修复分支 `fix/ht-execution-20261113`。

## 改动

1. **膨胀误拒**：当前 CMU HT-only 局部规划和控制输出统一按车辆朝向检查原始障碍与矩形车体包络，避免外接圆覆盖旁边障碍造成自锁。沿墙前进、倒车可以通过；转弯途中车角碰墙仍被拒绝。使用该实验已有 `vehicleLength=0.6`、`vehicleWidth=0.6` 配置，并包含栅格和扫掠采样裕量。这不是新测量的 Scout URDF 尺寸，切换车型必须同步配置两节点尺寸。车身真实相交、低 HT 分数、未知支撑和地图过期仍拒绝，不清空障碍图。
2. **恢复慢**：用制动距离控制代替长时间比例收敛尾段；位置采用沿程/横向误差和航向判据，允许小幅终点越过；连续两秒没有推进就停止并释放恢复控制。恢复中的外部限速与姿态减速也生效。保持原 0.15m/s、0.5rad/s 上限及加速度约束。
3. **审计一致性**：命令诊断记录车体包络版本、尺寸和支撑半径，独立 Python 审计支持新旧两种包络，不改历史验收回执。

## 验证

- 完整编译 localPlanner、pathFollower、原门禁测试、原恢复测试及新增执行测试。
- 两组 CTest 通过；新增测试验证贴墙退出、转弯碰撞、真实障碍/未知/低分拒绝、端点越界、动态限速、无进展退出和倒车恢复。
- 独立 Python 审计六项检查通过。
- 同一路线、同一20ms控制周期与5ms积分的旧/新控制函数对比：第一次 **7.80→6.14秒（减少21.3%）**，第二次 **11.92→8.52秒（减少28.5%）**。路线依据既有恢复形状构建；不是原始录包重放，也不是新实车成绩。

## 边界

修复作用于本分支 CMU 适配器，没有改动或部署独立 Scout 实车执行链。原始现场 CDR 夹具不在当前主机，旧 ht_recovery_test 只编译未执行；未开启 Gazebo、新600秒实验或实车运动。仍需原场景闭环验证，不能宣称所有当前位置拒绝或实车停车已解决。

恢复仍采用离散转向/前后动作及逐段停稳，搜索代价尚未完整计入实际收敛时间。本次直接缩短执行尾段，未另行改恢复路线优化器。探索收益下降、mapper观测方差生命周期缺陷均不在本补丁范围。
